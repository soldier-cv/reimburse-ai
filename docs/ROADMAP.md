# 产品改进路线图

以下能力已在 **3.3.0**（2026-11-12）实现。本文档保留当时的问题背景与最终方案，便于对照，不再作为待排期清单。

优先级按「影响日常使用 → 数据正确性 → 效率提升」排序。R-05、R-06、R-07 共用一套归属月与状态机，已一起落地。

## 已实现：交互基础

### R-01 统一点击反馈

原先异步操作只在结束后弹 toast，请求期间按钮没有状态，存在重复提交风险。

**已实现**：`api()` / `downloadBlob()` 维护全局在途计数，顶部细进度条延迟 200ms 出现；异步按钮统一 pending（spinner、文案、禁用）；AI 面板就地显示成功或失败原因；toast 有图标、按时长关闭，失败可手动关闭；任意点击 100ms 内有按下反馈。覆盖测试连接、获取模型、保存、导出、批次提交、记录到账、令牌签发/吊销/重新签发、删除、上传等。

### R-02 日期选择控件

原先全站依赖浏览器原生 `input[type=date]` / `type=month`，移动端和月份选择难用。

**已实现**：自研 `DateField`、`MonthField`，点击即弹日历，支持今天/本月、清空、键盘输入、移动端底部弹层，配色沿用 slate。未引入第三方日期库。可配置禁用未来日期。默认「今天」使用本地日期（Asia/Shanghai）。

### R-03 页面内使用指南

**已实现**：独立「使用指南」模块（侧边栏与页头问号），全页文档 + 锚点；界面少量「?」跳到对应章节。正文是仓库内 `docs/USER_GUIDE.md`，由 `GET /api/help/user-guide` 提供，不另写一份会漂移的正文。内容覆盖口径、采集、归属月、状态机、薪资计划、导出、成员、Agent、预览和常见问题。

## 已实现：采集与账本主流程

### R-04 票据在线预览

原先点击缩略图会下载整文件并离开页面；附件缩略图对图片直接返回原图。

**已实现**：本机生成预览，不接第三方。PDF 用 PyMuPDF 按页渲染 JPEG（长边 1600、质量 80），图片用 Pillow 生成 1600px 并校正 EXIF，缓存到 `uploads/user_N/previews/`。接口：`GET /api/capture/drafts/{id}/preview?page=N` 与 `GET /api/attachments/{id}/preview?page=N`，响应头带页数。前端全屏预览支持缩放、拖动、翻页和下载原件。OFD 提示暂不支持并提供下载。同一页只渲染一次；列表缩略图保持小图。

### R-05 确认入账时填写归属月

**已实现**：`CaptureDraft` 有独立 `period`，默认由发生日期带出，确认时可改。按公司批量确认可一次设置整组归属月。台账展示和筛选使用确认后的归属月。已提交后归属月按 R-06 锁定。批次归属月由所选应收汇总并校验一致。迁移：已有应收保持现值；旧草稿无 period 时按 `occurred_on` 推导。

### R-06 应收台账与状态机

**已实现**：只有待提交、被驳回可勾选归集，其余禁用并说明原因。列表增加归属月、创建日期。合并 PDF 和财务包从导出中心和批次详情发起。状态机：待提交 →（归集）→ 已提交 → 部分到账 → 已到账；被驳回可退回待提交；已放弃为终态。已提交后锁定金额、事项、公司、类别、归属月。批次级「撤回提交」是主入口；单笔从已提交批次退出，走草稿态下的移出。已提交禁止删除，只能放弃并留审计。非法变更由后端拒绝。

### R-07 批次管理

**已实现**：界面提供取消批次（展示笔数和金额）。草稿批次可移出单笔、添加应收。已提交尚未到账的批次可「撤回提交」（原因 + 审计），回到草稿再调整。已到账/部分到账不可拆，并明确提示。`POST /api/batches/{id}/unsubmit`、`POST /api/batches/{id}/items`。

### R-08 收件箱批量确认

**已实现**：全选/反选；长列表操作栏吸顶。确认前弹出汇总：笔数、金额、公司、归属月、缺金额或缺公司的草稿。去掉收件箱的「追加到已有应收」，只保留应收详情里的「从收件箱追加」。支持按公司分组批量确认。

### R-09 上传入口与压缩包反馈

**已实现**：按钮文案为「上传票据（进收件箱）」。上传结果说明生成草稿数、跳过数、失败或不支持格式的原因；嵌套 zip 与不支持格式不再静默吞掉。上传期间按钮 pending。

## 已实现：账本与权限

### R-10 固定月薪与薪资计划

**已实现**：新模块「薪资计划」：公司、月薪、发薪日、生效日期、停发日期。按月生成待提交工资应收（`kind=payroll`）。打开应用时补齐缺失月份，设置里可手动补齐。不使用后台定时任务。涨薪通过结束旧计划、新建新计划；补发和年终奖可手工录入。停发后不再生成；同一公司同一归属月不重复。到账截图仍按现有 `payroll_match` 核销。

### R-11 成员模块

**已实现**：界面明确「成员 = 独立账本」，管理员不能查看成员账本。默认只创建普通成员；创建管理员需显式二次确认（`confirm_admin`）。停用/启用：停用后无法登录，数据保留，`session_version` 提升使现有会话失效。删除改为软删除，并只清理该用户 `uploads/` 下的文件。

### R-12 令牌复制与权限

**已实现**：仍只存 SHA-256，不明文回显，不改可逆加密。新增「重新签发」，旧令牌立即失效，新明文只出现一次。可按应收、批次或月份打包原始文件（扩展 `POST /api/export/attachments`，`scope=export`）。Agent 可读取 AI 配置的只读摘要（是否启用、模型名称），不含密钥。继续禁止账号管理、令牌管理、AI 密钥写入、初始化管理员。写操作保留审计；令牌继续支持过期时间与最小范围。

## 已实现：日常习惯

1. **重复票据提醒**：相同 sha256 或相同发票代码+发票号再次上传或确认时提示，仍可强制确认。
2. **看板待办**：未确认草稿、本月待提交金额/笔数、已逾期、待核销或待生成的工资。
3. **公司自动带出**：只有一家时默认选中；多家按最近使用排序。
4. **手机拍照上传**：提供「拍照上传」入口，`capture="environment"`，同时保留从相册选择。

## 已实现：批次到账日期

批次「记录到账」弹出表单（`DateField`），到账日期默认当天（本地时区），用户可改后再提交 `POST /api/batches/{id}/payment`。可选备注，默认「批次到账」。不选日期时后端仍默认当天。请求期间按钮 pending。

## 已拍板的设计（3.3.0）

- 归属月写在草稿上，确认时可改；历史应收保持现值。
- 已提交但尚未到账的批次可以撤回，必须填原因并记审计；已到账/部分到账不可撤回、不可拆。
- 令牌只存哈希，只能重新签发，不明文回显。
- 工资在打开应用时补齐缺失月份，设置里同时提供手动补齐；不上后台定时任务。
