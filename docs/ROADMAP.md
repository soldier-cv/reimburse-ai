# 产品改进路线图

本文档整理 2026-11-12 需求评审中的问题、判断与改造方向，供后续排期使用。待办同步记录在 OpenChamber 项目面板；本文档只描述问题与方向，不代表已排期或已实现。

优先级按「影响日常使用 → 数据正确性 → 效率提升」排序。R-05、R-06、R-07 共用一套归属月与状态机设计，建议一起实施。

## P0 交互基础

### R-01 统一点击反馈

**现状**：异步操作只在结束后弹一个 3.2 秒的 toast，请求期间按钮没有状态，最长可静默 20 秒（如「测试连接」）。按钮没有按下态；请求期间不禁用，存在重复提交风险。

**建议**：

- `api()` / `downloadBlob()` 维护全局在途计数，顶部显示细进度条，延迟 200ms 出现避免闪烁；
- 异步按钮统一 pending：spinner、文案变化、禁用，防止重复提交；
- 结果就地显示（例如 AI 面板常驻「连接成功」或失败原因），toast 只作补充；
- toast 增加图标、按类型设置时长、失败可手动关闭；
- 覆盖测试连接、获取模型、保存、导出、批次提交、记录到账、令牌签发/吊销、删除等。

**验收**：任意一次点击在 100ms 内有按下反馈；请求超过 300ms 时按钮进入 pending；失败原因留在页面上可复现。

### R-02 日期选择控件

**现状**：全站十余处 `input[type=date]` / `type=month`，依赖浏览器原生控件；移动端和月份选择难用，样式与页面不一致。

**建议**：自研两个 Vue 组件（`DateField`、`MonthField`），点击即弹日历，支持今天/本月快捷、清空、键盘输入、移动端底部弹层，配色沿用 slate。项目无构建、Vue 与 Tailwind 走 CDN，暂不引入第三方日期库；确实需要时间或日期范围时再评估。

**验收**：所有日期/月份输入替换完成，桌面与手机均可完成选择，禁用未来日期等约束可配置。

### R-03 页面内使用指南

**现状**：界面缺少解释，成员、归属月、批次等概念需要口头说明。

**建议**：不在表单里堆解释文字，新增独立「使用指南」模块（侧边栏入口或页头问号，全页文档 + 锚点），界面只保留少量「?」链接跳转到对应章节。正文放仓库内 markdown，随代码版本化；接口或规则变化时同步修改。

内容至少覆盖：产品口径（应收是唯一事实、部分到账、金额以分存储）、采集与收件箱（压缩包、识别、确认）、归属月与发生日期的区别、应收台账与批次状态机、薪资计划与到账核销、导出中心、成员与账本隔离、Agent 令牌与权限、常见问题与已知边界（不做退款/税务验真、OFD 不自动识别等）。

**验收**：新用户不靠口头说明，能走通「上传 → 确认 → 归集 → 提交 → 到账 → 导出」。

## P1 采集与账本主流程

### R-04 票据在线预览

**现状**：点击缩略图走 `openBlob()`：先下载整个文件，再 `window.open(blobUrl)`。桌面浏览器可预览 PDF，手机与微信内置 WebView 通常变成下载；核对金额时还会离开当前页面。上传时只生成 360px 缩略图，没有足够看清金额的中间尺寸；附件缩略图对图片直接返回原图，对 PDF 每次请求都重新渲染。

**已定方案**：本机生成预览，不接第三方服务，暂不引入 S3。

- PDF 用 PyMuPDF 按页渲染 JPEG（长边 1600、质量 80），按需生成并缓存到 `uploads/user_N/previews/`；
- 图片用 Pillow 生成 1600px 预览并校正 EXIF；
- 新增 `/api/capture/drafts/{id}/preview?page=N` 与 `/api/attachments/{id}/preview?page=N`，Header 鉴权，响应头带页数；
- 前端全屏预览：缩放、拖动、左右翻页、页码、下载原件；缩略图不再触发下载；
- OFD 明确提示「暂不支持在线预览」并给下载入口；
- 预留存储读写接口，待多实例或容量超过 50–100GB 再迁移对象存储。

**验收**：手机与桌面都能在应用内查看 PDF 每一页和图片；同一页只渲染一次；列表不再传输原图。

### R-05 确认入账时填写归属月

**现状**：归属月由发生日期推导（`period_from_date(occurred_on)`）。确认接口没有 `period` 参数，应收编辑也没有该字段，只有批次弹窗要求填写归属月。发票发生日与报销归属月、工资归属月与发薪日可能跨月，推导会出错。

**建议**：

- 给 `CaptureDraft` 与 `Receivable` 增加独立的 `period`，历史数据保持现值；
- 收件箱卡片增加归属月输入，默认按发生日期带出，确认时显式确认；
- 应收台账只展示和筛选，不再要求用户填写；
- 批次归属月由所选应收汇总并校验一致性；
- 按公司/月份批量确认时，允许一次设置整组归属月。

**验收**：归属月与发生日期可以不同；批次、导出、看板统计使用用户确认的归属月。

### R-06 应收台账与状态机

**现状**：勾选对所有状态开放，后端才报错；列表没有归属月和创建日期（接口已返回）；列表上保留合并 PDF、财务包按钮；已提交的应收仍可编辑、删除，后端只拦截了已有到账的记录。

**建议**：

- 只有待提交、被驳回可勾选归集，其余禁用并说明原因；
- 列表增加归属月、创建日期两列；
- 移除列表上的合并 PDF、财务包按钮，统一从导出中心和批次详情发起；
- 补齐状态机：待提交 →（归集）→ 已提交 → 部分到账 → 已到账；被驳回可退回待提交；已放弃为终态；
- 已提交后锁定金额、事项、公司、类别、归属月，修改必须走「撤销提交」（记录原因、时间、操作人）；
- 已提交禁止删除，只能放弃并留审计；
- 校验放在后端，前端隐藏和禁用只是配合。

**验收**：任何非法状态变更都会被后端拒绝；撤销提交可在审计日志中追溯。

### R-07 批次管理

**现状**：后端已有取消接口（未到账可取消，应收退回待提交），但界面没有入口；草稿批次只能改标题、期间、预计到账和备注，不能移出或添加单笔。

**建议**：

- 草稿批次支持移出单笔、添加应收、取消拆解；
- 已提交批次提供「撤回提交」（填写原因并审计），撤回后回到草稿再调整；
- 已到账批次不可拆，走调整流程或明确提示不支持；
- 批次列表和详情补齐上述入口，操作前展示影响范围（笔数、金额）。

**验收**：误归集可以在提交前方便修正；提交后撤回有完整记录；已到账不会被破坏。

### R-08 收件箱批量确认

**现状**：已有勾选和顶部「确认入账（N）」，但缺少全选/反选、操作栏吸顶、确认前汇总；卡片上的单条确认按钮更显眼。追加入口同时出现在收件箱和应收详情，职责重复。

**建议**：

- 增加全选/反选，操作栏在长列表中吸顶；
- 确认前弹出汇总：笔数、金额、公司、归属月、缺金额或缺公司的草稿；
- 去掉收件箱的「追加到已有应收」，只保留应收详情中的「从收件箱追加」；
- 支持按公司分组批量确认。

**验收**：几十张草稿可以一次核对、一次确认；追加操作只从应收侧发起。

### R-09 上传入口与压缩包反馈

**现状**：顶部「上传凭证」和收件箱上传共用同一个 file input，`accept` 已包含 `.zip`，后端会把压缩包内每个文件拆成草稿，成功后跳转收件箱。「新增应收」直接打开应收弹窗。能力已具备，但结果反馈不足：只提示上传文件数，不说明生成几条草稿、跳过几个、失败原因；不支持的格式和嵌套 zip 静默跳过。

**建议**：

- 按钮文案明确「上传票据（进收件箱）」；
- 上传结果显示生成草稿数、跳过数、失败原因；
- 压缩包内不支持的格式给出汇总提示；
- 上传按钮在请求期间进入 pending。

**验收**：用户上传压缩包后能立刻知道哪些文件被接收、哪些被跳过以及原因。

## P2 业务能力

### R-10 固定月薪与薪资计划

**现状**：没有周期薪资。工资应收只能手动新增，或识别工资条后确认；工资到账截图（`direction=in`）只核销已有工资应收，不新建应收。每月固定薪酬需要手动补建，容易漏。

**建议**：新增「薪资计划」：公司、月薪、发薪日、生效日期、停发日期。按月生成待提交工资应收，到账截图按备注月份核销。需要覆盖涨薪、补发、年终奖、试用期、离职停发；生成方式建议默认「打开应用时补齐缺失月份」，避免后台任务带来额外复杂度。

**验收**：配置一次后，每月工资应收自动出现；到账截图能匹配并核销；停发后不再生成。

### R-11 成员模块

**现状**：成员是独立账本账号。管理员可以建号、重置密码、删除，但读不到别人的账本；所有业务查询都带 `user_id`。新建成员的实际用途是给家人/同事各自记账，或给 Agent 建隔离账号。界面没有说明；角色下拉可以创建第二个管理员；只能硬删除，数据库有级联但 `uploads/` 文件不会清理；没有停用/启用。

**建议**：

- 界面明确「成员 = 独立账本」；
- 默认只创建普通成员，管理员角色需要显式二次确认；
- 增加停用/启用，删除改为软删除并清理磁盘文件；
- 说明管理员不能查看成员账本。

**验收**：创建成员时用户清楚用途和权限边界；停用后无法登录但数据保留。

## P3 Agent

### R-12 令牌复制与权限放大

**现状**：令牌只存 SHA-256，明文仅在签发时返回，弹窗关闭后无法再次复制。弹窗内的复制按钮可以多次点击。业务权限已覆盖采集、台账、批次、到账、导出；账号、令牌、AI 密钥是刻意禁止的。取件能力不足：只能逐个下载，或导出带封面和 Excel 的财务包，没有按应收/批次/月份一次打包原件的接口。

**建议**：

- 保持令牌不可回显，补充「重新签发」并明确旧令牌立即失效；若确实需要长期可复制，再评估可逆加密存储（安全降级，需单独确认）；
- 增加批量取件：按应收、批次或月份打包原始文件；
- 允许 Agent 读取 AI 配置的只读摘要（是否启用、模型名称），不包含密钥；
- 继续禁止账号管理、令牌管理、AI 密钥写入、初始化管理员；
- 所有 Agent 写操作保留审计，令牌支持过期时间与最小范围。

**验收**：Agent 能独立完成「取件 → 识别 → 建账 → 归集 → 提交 → 导出」，不需要打开 Web 页面；敏感操作仍被拒绝并记录。

## 待确认的决策

1. 归属月的数据模型：草稿字段随确认写入，还是确认接口按草稿逐条传参。
2. 已提交批次的撤回规则：是否允许撤回、谁能撤回、撤回后是否保留原提交时间。
3. Agent 令牌是否改为可逆加密存储；如改，密钥如何纳入部署管理。
4. 薪资计划的生成时机：打开应用时补齐、每月定时任务，还是手动一键生成。

## 实施约定

- R-05、R-06、R-07 作为一组设计，先定状态机再改界面。
- 业务规则以后端校验为准，前端只做引导。
- 每项完成后按补丁号更新 `app/main.py` 版本与 `CHANGELOG.md`。
- 测试使用隔离临时库与上传目录，禁止指向生产数据。
